# Первая практика — мини-анализ ипотечных записей

Откройте ноутбук практики. В нём находятся заголовки, готовые примеры и пустые кодовые ячейки для A–G. Условия заданий читайте здесь; текстовые ответы и определения записывайте в отчёт README рядом с ноутбуком. Порядок работы — сверху вниз. Практика рассчитана на одну пару.

## 1. Подготовка и данные

Запустите окружение по инструкции курса, откройте ноутбук и выполните раздел «Подготовка». Проверьте путь Python, версию pandas и рабочую папку. Shift+Enter выполняет ячейку. Команда assert проверяет условие: при False останавливает выполнение с ошибкой. В первой ячейке она проверяет наличие папки данных.

DATA = Path("../data") указывает на папку data рядом с папкой ноутбука. Запускайте ноутбук в его исходном расположении. Все CSV уже приложены; скачивать данные на занятии не нужно.

HMDA — публичная ипотечная отчётность США. Наш набор относится к покупке жилья в Вашингтоне, округе Колумбия, за 2023 год. Сначала выполняем примеры на reading_example.csv: шесть реальных записей, специально подобранных для ручного разбора. Затем используем decisions.csv: 6 830 записей с исходами 1–3.

| Поле | Значение |
|---|---|
| source_row | Номер строки исходного CSV |
| activity_year | Отчётный год |
| lei | Код финансовой организации |
| county_code | Код территории |
| action_taken | Исход: 1 — выдано; 2 — одобрено, предложение не принято; 3 — отказ |
| loan_amount | Сумма, USD |
| income | Годовой доход, тысячи USD |

[Карточка данных](../data/card.md) содержит происхождение и полный словарь. Код организации и код территории читаются как строки через dtype. После загрузки example найдите в выводе каждое из семи полей.

## A. Разделитель CSV

Прочитайте reading_example.csv ещё раз, задав sep=";". Сохраните результат в wrong_sep, затем покажите таблицу и её shape. Сравните её с example. В отчёте A объясните, почему результат чтения отличается и какой разделитель нужен этому файлу.

Сохраните правильную example для следующих шагов. Результат задания — отдельная wrong_sep и объяснение по её структуре.

## B. Частичное чтение

В первой команде прочитайте только первые три записи reading_example.csv через nrows=3 и сохраните их в preview. Во второй прочитайте все записи, но только action_taken и income через usecols; сохраните их в small_columns. Покажите shape обеих таблиц.

В отчёте B объясните, какой параметр ограничивает строки, какой — столбцы и чем nrows=3 отличается от head(3). Укажите, какие строки и поля видны в каждом выводе.

## C. Выбор столбцов и просмотр

Сначала выполните предоставленные примеры выбора outcomes и selected. Посмотрите их типы через type. Затем самостоятельно выберите из example столбцы source_row и loan_amount и покажите первые две строки. Назовите результат amount_view. Отдельно покажите shape, columns и info исходной example.

В отчёте C объясните различие между example["action_taken"] и example[["action_taken"]], а также единицы loan_amount. Укажите, изменился ли размер исходной example после просмотра.

## D. Доля выдач на маленьком примере

Выполните готовый пример одобрений. В нём коды 1 и 2 помечаются через isin, sum считает True, а len(example) даёт общее количество записей.

По такому же порядку посчитайте выдачи, то есть исход 1. Создайте issued_flag, затем n_issued и small_origination_rate. Покажите логические признаки, количество выдач, общее количество и процент. Сверьте расчёт вручную по шести исходам. В отчёте D запишите условие и дробь для каждой из двух долей.

## E. Две доли на основном наборе

Выполните предоставленную загрузку decisions.csv. В переменных full_outcomes и full_n уже находятся исходы и общее количество записей. Посмотрите shape и частоты исходов.

Самостоятельно получите full_approved и full_issued, затем full_approval_rate и full_origination_rate. Для одобрений используйте исходы 1 и 2, для выдач — исход 1. В обеих формулах общее количество — все строки decisions.

Выведите для каждого показателя условие отбора, числитель, знаменатель и процент. В отчёте E объясните, что означает каждый показатель и к какому году, территории и набору он относится. Не переносите доли с шести подобранных строк на основной набор.

## F. Проверки расчёта

Выполните блок «Проверка входных данных». Он проверяет непустоту таблицы и допустимые исходы, затем показывает количество пропущенных доходов. Выражение isna().sum() считает пропуски: isna отмечает их True, sum складывает эти отметки.

Получите full_denied — число отказов. Самостоятельно запишите assert для двух свойств:

- full_approved + full_denied равно full_n;
- количество выдач неотрицательно, не больше количества одобрений, а количество одобрений не больше full_n.

Проверьте также, что рассчитанные доли лежат от 0 до 1. В отчёте F объясните, какие ошибки заметят эти проверки. Нужен ли доход для самого расчёта доли одобрений? Обоснуйте решение, сохраняя выбранный набор записей.

## G. Два исправления отчёта

В ноутбуке показан расчёт, названный approval_rate — «доля одобрений». Сопоставьте его условие с определением из E.

Подготовьте два отдельных исправления: в первом сохраните название показателя и исправьте условие; во втором сохраните условие и подберите верное название переменной. Сохраните оба варианта кода. В отчёте G объясните, почему одному результату нельзя произвольно дать любое название.
