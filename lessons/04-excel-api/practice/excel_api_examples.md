# Учебные примеры по Excel и API

Используйте эти примеры для повторения перед домашней работой. Готовый код и упражнения A–D находятся в [учебном ноутбуке](../work/notebook.ipynb). Условия для работы в паре приведены в [задании P05](guide.md).

## Источники и обозначения

[Карточка данных](../data/card.md). HMDA содержит ипотечные записи 2023 года: source_row — номер исходной строки, lei — код организации, activity_year — год, action_taken — исход 1, 2 или 3. Сумма кредита loan_amount указана в USD, income — в тысячах USD за год. county_code обозначает территорию записи.

hmda_exchange.xlsx — учебная книга из сохранённых реальных данных. Лист organizations содержит lei, name, period и count; name — название, period — отчётный год. reading_example содержит ипотечные строки. filers_2023_dc.json — справочник HMDA, список организаций находится под institutions.

gleif_page_01.json и gleif_page_02.json — реальные ответы GLEIF для выбранных LEI, полученные 10 октября 2026 года. data — список записей; id — LEI; attributes.entity.legalName.name — юридическое имя; attributes.entity.legalAddress.country — страна юридического адреса; attributes.entity.status — статус юридического лица. Это сведения реестра на момент снимка. Суффикс _current в таблице сохраняет это различие с годом HMDA.

manifest.json хранит запрошенные selected_lei, адрес first_url и список pages с именами файлов, временем, статусом, форматом и sha256. meta.pagination.total сообщает ожидаемое количество записей, links.next — адрес продолжения. Исходные ответы уже включены в комплект; обязательная часть выполняется без сети.

## Начало и инструменты

Выполните подготовку и чтение исходников. decisions — ипотечные записи; page1/page2 — словари ответов; manifest — сопровождающий словарь; book — словарь листов Excel. До самостоятельной работы найдите data, meta и links в первой странице.

json.load читает открытый файл, json.loads — JSON-текст, json.dumps превращает Python-объект в JSON-текст. read_excel с sheet_name=None возвращает словарь листов, с именем листа — DataFrame. json_normalize разворачивает записи в таблицу; sep="." сохраняет путь вложенного поля в названии. rename меняет названия столбцов, а не их значения.

Request(...).prepare() собирает запрос без отправки. raise_for_status проверяет HTTP-статус; json() разбирает тело. Content-Type и обязательные поля проверяются отдельно. Функция collect_pages последовательно загружает страницы через loader, проверяя ссылки и итоговое количество. cached_loader читает их из словаря cache. hashlib.sha256(body).hexdigest() вычисляет контрольную сумму исходных байтов.


## 01. Два формата одного источника

Прочитайте page1, page2 и manifest. Найдите список организаций и сведения о страницах. Затем book покажет названия листов и их размеры. Книга Excel создана для упражнения из реальных сохранённых данных.

## A Чтение справочника

Прочитайте organizations из Excel с lei, name, period. Из filers_2023_dc.json получите таблицу institutions и те же поля. Приведите lei к string, отсортируйте обе таблицы по lei/period и сравните через assert_frame_equal. В отчёте назовите лист, смысл строки и ключ.

## 02. Полный пример нормализации

Готовый пример показывает путь к юридическому имени первой страницы. При развороте otherNames одна строка начинает означать одно другое имя. Сопоставьте количество строк с исходными списками.

## B Справочник из двух страниц

Объедините списки data страниц, получите плоскую таблицу, выберите id, юридическое имя и страну юридического адреса. Переименуйте их в lei, legal_name_current, legal_country_current. Проверьте известность и уникальность lei и точное совпадение с selected_lei. Объясните смысл строки и географического поля.

## 03. GET без сети и настоящий сохранённый ответ

Подготовленный URL сравнивается с сохранённым запросом. Объект response восстановлен из файла и метаданных; это не новый сетевой ответ. Поле _content устанавливается вручную только для этой демонстрации. Затем decode_json_response проверяет статус, формат и наличие data.

## C Два сбоя ответа

Создайте две отдельные копии response через deepcopy: у первой статус 429, у второй заголовок Content-Type равен text/html при прежнем успешном статусе. Передайте их в decode_json_response и покажите остановку нужным исключением. HTTPError и ValueError соответствуют разным проверкам. Ветка else должна сообщить, если ошибка не обнаружена. Исходный response не меняйте.

## 04. Обход страниц с проверками

cache связывает сохранённый адрес с его страницей. collect_pages получает страницы через cached_loader, накапливает data, следует next и проверяет завершение. Прочитайте функцию по этим шагам, затем посмотрите collected. Встроенные ошибки здесь означают остановку неполного получения.

## D Сохранение и проверка пакета

Скопируйте байты обеих страниц в ../results/raw и сохраните рядом manifest.json. До копирования сверьте SHA-256. Из collected получите lookup.csv с LEI, именем, страной адреса и статусом юридического лица; названия добавленных полей заканчиваются _current. Прочитайте CSV повторно, сохранив lei как string, и сравните значения. Создайте acquisition_report.json: количество страниц, строк и уникальных LEI, результат проверки хешей, публикация версии, время загрузки и временное ограничение.
