## Слайд 6. Пропуск и ноль

## Слайд 11. Текст в число и ошибки преобразования

pd.to_numeric получает Series с текстом и возвращает числовую Series. Обычная строка "275000.0" превращается в число. Для oops число получить нельзя. Параметр errors="coerce" выбирает реакцию: поставить отсутствующее значение вместо остановки с ошибкой.

После преобразования одного isna недостаточно: он найдёт и старые пропуски, и вновь возникшие. Поэтому берём два условия: исходное поле было известно — notna; полученное число неизвестно — isna. Объединяем их знаком &: оба условия проверяются для каждой строки. Маской выбираем исходные source_row и loan_amount. В выводе увидим oops. На практике тем же способом отдельно проверите income и найдёте BAD.

```python
numeric_amount = pd.to_numeric(export["loan_amount"], errors="coerce")
parse_error = export["loan_amount"].notna() & numeric_amount.isna()
print(export.loc[parse_error, ["source_row", "loan_amount"]])
```

## Слайд 16. Необычно большая сумма

Текст oops не задаёт число, а большая числовая сумма может быть реальной. Чтобы выделить необычные суммы для просмотра, воспользуемся квартилями. Q1 — значение, ниже которого примерно четверть наблюдений; Q3 — значение, ниже которого примерно три четверти. Между ними находится средняя половина. Разность Q3 и Q1 называется межквартильным размахом, IQR.

quantile([0.25, 0.75]) возвращает две границы. В нашем наборе Q1 равен 315000, Q3 — 755000 долларов. Прибавим к Q3 полтора размаха: получим 1415000. Суммы выше порога отметим для проверки. Их 355. Это способ выбрать необычные значения для просмотра. Решение об исключении потребует выяснить, нарушают ли они смысл поля или условия анализа.

```python
amount = decisions["loan_amount"]
q1, q3 = amount.quantile([.25, .75])
iqr = q3 - q1
upper_flag = q3 + 1.5 * iqr
print(q1, q3, upper_flag)
```

```python
flagged = decisions.loc[amount.gt(upper_flag)]
print("Кандидатов на разбор:", len(flagged))
flagged[["source_row", "loan_amount", "action_taken"]].head(5)
```

## Слайд 17. Среднее и медиана суммы

Среднее — сумма всех значений, делённая на их количество. Очень большая сумма увеличивает его. Медиана — середина отсортированного ряда; при чётном количестве берём среднее двух центральных значений. Поэтому она меньше реагирует на величину самых больших сумм.

В исходном наборе средняя сумма около 670199 долларов, медиана 505000. Теперь создадим without_tail, где суммы не выше вычисленного порога, и снова посчитаем среднее. Оно уменьшится. Важно назвать, для какой группы получено каждое число: первый результат относится ко всем нашим решениям, второй — к ограниченной по сумме группе. Оба расчёта полезны для сравнения чувствительности. Исходный набор decisions оставим целым.

```python
print("Исходный mean/median:", amount.mean(), amount.median())
without_tail = decisions.loc[amount.le(upper_flag)]
print("Без флага хвоста:", len(without_tail), without_tail["loan_amount"].mean())
```

## Слайд 18. Пересечение условий

Построим две уже знакомые маски на исходной таблице: неизвестный доход и отказ. Первая содержит 342 True, вторая — 691. Если сложить эти количества, получим 1033. Но 65 записей попали в обе группы и были посчитаны дважды.

Вертикальная черта | даёт True, если для строки выполнено хотя бы одно условие; & требует оба. Поэтому объединение содержит 968 строк, пересечение — 65. Равенство для проверки: 342 плюс 691 минус 65 равно 968. Здесь отказ — просто второе условие для примера, сами отказы мы сохраняем в анализе. В журнале качества по той же причине отдельно считаем частоту каждой проблемы и число уникальных строк, затронутых хотя бы одной проблемой.

```python
missing_mask = decisions["income"].isna()
denial_mask = decisions["action_taken"].eq(3)
print(missing_mask.sum(), denial_mask.sum())
print((missing_mask | denial_mask).sum(), (missing_mask & denial_mask).sum())
```

## Слайд 19. Карантин и баланс

В учебной копии мы умеем убрать внешние пробелы и точные повторные доставки. Для двух других строк правильное значение по экспорту восстановить нельзя: в одной сумма oops, в другой исход 88. Поместим их в отдельную таблицу quarantine. Это и называем карантином: строки остаются доступными вместе с причиной, но не входят в подготовленный слой clean.

Строку с BAD в income сохраним в clean: после преобразования у неё неизвестен доход, а исход известен. Ошибку преобразования запишем в журнал. Получаем баланс: 6832 входных строки состоят из 6828 строк clean, двух карантинных записей и двух повторных доставок. Проверим равенство, чтобы обнаружить незаметную потерю строк. Оно подтверждает учёт количества; причины распределения мы только что задали отдельно.

|Часть результата|Строк|Что произошло|
|---|---|---|
|Входной экспорт|6832|До исправлений|
|Повторные доставки|2|Оставлено первое вхождение|
|Карантин|2|Сумма oops или исход 88|
|Подготовленные записи|6828|Удовлетворяют правилам|

## Слайд 20. Функция очистки

Теперь соберём уже разобранные шаги в clean_export. source — входная таблица, out — её копия. Сначала проверяем разные версии одного известного номера, затем исключаем точные повторные доставки. После этого убираем пробелы и по очереди преобразуем четыре поля в числа, сохраняя число ошибок каждого преобразования.

Для каждой оставшейся строки создаём текст reason. При нарушении правила дописываем причину: отсутствует номер, неверна сумма, исход или территория. Где reason пуст, получаем clean. Для карантина берём исходные строки source: там остаются oops и 88, а рядом добавляется причина. audit — обычный словарь с количеством входных строк, повторов, clean, карантина и ошибок преобразования. return возвращает эти три объекта. На экране готовая функция; прочитаем её по этапам и выполним один вызов.

```python
clean, quarantine, audit = clean_export(export)
print(audit)
quarantine
```

## Слайд 21. Проверки результата и входа

assert проверяет утверждение. Если оно истинно, выполнение продолжается. Если ложно, возникает AssertionError и дальнейший код не выполняется. Проверим уникальность source_row, допустимость исходов, положительность сумм и баланс. Для логического ряда all означает: условие должно быть истинно в каждой строке.

Для сохранности входа используем assert_frame_equal из pandas.testing. Он сравнивает таблицы вместе с типами и индексами. Сравним export с raw_copy, сделанной при загрузке: исходник должен остаться тем же. Затем ещё раз вызовем функцию на том же export и сравним clean, карантин и журнал. Совпадение показывает повторяемость действий. Определения правил проверяем содержательно: например, заполнение дохода нулём тоже можно написать так, что два запуска совпадут.

```python
from pandas.testing import assert_frame_equal
assert_frame_equal(export, raw_copy)
assert clean["source_row"].is_unique
assert clean["action_taken"].isin([1, 2, 3]).all()
assert clean["loan_amount"].gt(0).all()
assert len(export) == len(clean) + len(quarantine) + audit["replays"]
```

```python
again, quarantine_again, audit_again = clean_export(export)
assert_frame_equal(clean, again)
assert_frame_equal(quarantine, quarantine_again)
assert audit == audit_again
```

## Слайд 22. Показатель после очистки

Применим одну функцию расчёта к исходным данным и результату очистки. В каждом случае отдельно печатаем количество одобрений и размер таблицы. В оригинале 6139 одобрений среди 6830 решений. В clean осталось 6137 одобрений среди 6828 записей: две строки с дефектами обязательных полей были исходно выдачами и ушли в карантин.

После округления до двух знаков оба процента выглядят одинаково: 89,88. Однако числители и знаменатели различаются. Поэтому в отчёте нужны и количества, и причины исключений. Отдельно посчитаем ту же долю среди clean с известным income. Подпись обязательно называет эту группу. Количество строк после отбора поможет читателю понять, за счёт чего изменился ответ.

```python
def show_approval(label, table):
    n_rows = len(table)
    assert n_rows > 0
    n_approved = table["action_taken"].isin([1, 2]).sum()
    print(label, n_approved, n_rows, f"{100 * n_approved / n_rows:.2f}%")

show_approval("Оригинал", decisions)
show_approval("После учебной очистки", clean)
complete_clean = clean.dropna(subset=["income"])
show_approval("Известный доход после очистки", complete_clean)
```

## Слайд 23. Файлы результата и происхождение

Передаём не только clean.csv. В quarantine.csv сохраняем исходные значения спорных записей и reason. В quality_report.json — численный журнал audit. Код функции объясняет последовательность преобразований. Отдельный README говорит, какой вопрос решали и почему выбрали эти правила.

Такая связь между исходным файлом, преобразованием и результатом называется происхождением данных, или data lineage. В карточке снимка уже сохранены источник, параметры и контрольные суммы файлов. Контрольная сумма помогает проверить, что байты исходника не изменились. В README дополнительно укажем, что работали с учебной копией, какие исправления делали, сколько строк исключили и какой знаменатель использован.
